# Осколок в Telegram: плеер, фон и музыка в профиле

Обновлено 23 сентября 2026. Бот: **@oskolokplayerbot**.

**Вывод:** поиск, коллекция, рекомендации и Интерференция подходят для Mini App. Полный эквивалент самостоятельного плеера с непрерывной очередью после закрытия WebView обещать нельзя. Для фонового прослушивания добавлен отдельный сценарий передачи аудиофайла в нативный плеер Telegram.

## Фоновое воспроизведение: четыре разных состояния

| Состояние | Что может Осколок |
| --- | --- |
| Mini App открыт | HTMLAudio + Web Audio, очередь, пословный текст и стеклянная сцена |
| Mini App свёрнут, WebView ещё жив | Воспроизведение зависит от ОС и клиента; код не ставит аудио на паузу из-за скрытой страницы, визуальные вычисления приостанавливаются |
| WebView выгружен или Mini App закрыт | JavaScript больше не управляет аудио и очередью; сервер не может заставить закрытый плеер продолжить |
| Файл открыт нативным плеером Telegram | Воспроизведением управляет Telegram; очередь Осколка и Интерференция в этот плеер не переносятся |

Это инженерная оценка жизненного цикла, не результат измерений на всех клиентах Telegram. Нужен реальный тест iOS/Android: сворачивание, блокировка, звонок, Bluetooth, смена сети, несколько минут в фоне.

Media Session добавляет системные кнопки, метаданные и позицию. Он не даёт приложению фоновой службы и не гарантирует сохранение процесса. В коде обновляются позиция/состояние и обрабатываются поддерживаемые кнопки. [Спецификация Media Session](https://www.w3.org/TR/mediasession/).

## Добавление музыки в профиль

Прямая запись через `account.saveMusic` доступна только пользовательским клиентам Telegram, не ботам. В Mini Apps SDK метода сохранения музыки в профиль сейчас нет. [account.saveMusic](https://core.telegram.org/method/account.saveMusic), [Mini Apps SDK](https://core.telegram.org/bots/webapps).

Для автоматической публикации пользователь подключает отдельную пользовательскую MTProto-сессию. На телефоне в профиле Осколка нужно открыть раздел **Telegram → Продолжить в боте**. Бот принимает номер в международном формате или контакт, затем код подтверждения и, при необходимости, облачный пароль. После успешного входа он предлагает вернуться в Mini App, где появляется подтверждение. QR остаётся вариантом для компьютера или второго устройства. Telegram выбирает способ доставки кода сам; SMS для сторонних приложений не гарантирован. [Авторизация Telegram](https://core.telegram.org/api/auth).

Код и пароль не сохраняются в базе и не пишутся в лог; бот пытается удалить сообщения с ними после обработки. Попытка входа живёт пять минут, повторная выдача кода и неверные ответы ограничены. Ссылка входа привязана к Telegram ID, подтверждённому Mini App: чужой аккаунт не сможет продолжить подключение. Готовая сессия хранится в зашифрованном серверном хранилище. У Telegram-чата есть собственная история доставки сообщений, поэтому пользователь должен учитывать это при выборе способа входа; QR не требует отправлять пароль боту.

Переключатель «Полная Telegram интеграция» включён по умолчанию. После подтверждённого начала воспроизведения сервер загружает MP3/M4A через `messages.uploadMedia` без создания сообщения в «Избранном» и вызывает `account.saveMusic`. При смене или паузе он вызывает `account.saveMusic` с флагом `unsave` для созданной им временной записи. Ручные записи в Telegram не удаляются. Через 90 секунд без heartbeat устаревший статус очищается. Если доступного полного файла нет, профиль Telegram не обновляется и в Осколке показывается причина.

Отдельная кнопка «В Telegram-профиль» вручную закрепляет выбранный трек; она не участвует в автоматической замене и тоже не создаёт запись в «Избранном». Используется полная сгенерированная TL-схема layer 229 из Teleproto с типизированным `account.SaveMusic`; сериализация запроса проверена тестами. Живой вызов сохранения и последующего удаления временного аудио проверен на подключённом аккаунте. Сообщения, созданные прежними версиями Осколка, нельзя безопасно отличить от личных файлов пользователя, поэтому их удаление остаётся ручным.

Бот использует `sendAudio`, который создаёт аудиосообщение для нативного музыкального плеера. Поддерживаются MP3/M4A; проект ограничивает передачу размером 49 МБ и готовыми файлами из кэша. Если файл не готов или формат не подходит, интерфейс показывает ошибку, а не успех. [Bot API sendAudio](https://core.telegram.org/bots/api#sendaudio).

В десктопной версии доступна загрузка файла для ручной отправки в «Избранное» Telegram. Треки не отправляются другим людям. Доставка в чат не означает добавления в профиль. Позицию нативного проигрывания Bot API нашему приложению не сообщает — синхронизировать с ним текст или продолжать его очередь автоматически нельзя.

## Привязка Telegram-профиля: что уже в коде

- При запуске через Telegram SDK передаёт `initData`; сервер проверяет HMAC, срок 24 часа, корректность пользователя и отсутствие дублирующихся полей. Недействительная подпись отклоняется.
- Идентификатор коллекции — `telegram:<id>`. Имя и фото берутся из проверенных данных, отображаются в исходном меню профиля.
- `userId` из URL/тела запроса больше не выбирает владельца данных. Чужой плейлист нельзя читать или менять по его ID.
- `TELEGRAM_MODE=true` требует подписанную сессию для личных API. Публичный профиль и каталожный аудиопоток доступны без неё. Токен хранится на сервере.
- Локальные тексты и порядок избранного разделены по Telegram-аккаунтам. Импорт текста пока не синхронизируется между устройствами.
- Учтены безопасные отступы. Локальная десктопная коллекция автоматически в Telegram-аккаунт не копируется.

Правила проверки `initData` описаны в [документации Telegram](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app).

## Что требуется для живого запуска

В серверном `.env` задать:

```dotenv
TELEGRAM_MODE=true
TELEGRAM_BOT_USERNAME=oskolokplayerbot
TELEGRAM_BOT_TOKEN=<токен бота, только на сервере>
CORS_ORIGIN=https://<домен приложения>
```

Frontend и API разместить под одним HTTPS-доменом с `/api` reverse proxy. В BotFather настроить Main Mini App/menu button на этот адрес. SDK загружается только при Telegram-запуске. Потребуется сервер с Node, Python/ffmpeg и постоянным хранилищем; эти процессы не запускаются внутри WebView.

Для временной проверки с телефона запустите из корня проекта `npm run mobile:test`. Команда соберёт приложение, поднимет сервер вместе с ботом, создаст HTTPS-туннель localhost.run, проверит страницу и API, затем обновит и проверит кнопку меню бота. При обрыве туннель автоматически переподключается и бот получает новый адрес. Повторный запуск команды заменяет предыдущий управляемый запуск; остановка — `npm run mobile:test:stop`. Текущий адрес записывается в `/tmp/oskolok-mobile-tunnel-url`, а лог при фоновом запуске можно направить в файл. Нужны `PORT`, `DATABASE_URL` и `TELEGRAM_BOT_TOKEN` в `.env`; для полноценной интеграции профиля также нужны `TELEGRAM_API_ID` и `TELEGRAM_API_HASH`. Для постоянного использования нужен собственный HTTPS-домен: анонимный туннель может оборваться или сменить адрес. Диалог бота работает через Bot API long polling; приветствие, справка, проверка подключения и отмена доступны командами `/start`, `/help`, `/status`, `/cancel`.

Сценарий перехода в бота, привязки того же аккаунта и авторизация по номеру проверены тестами с имитацией Telegram API. Живой проход нового входа с кодом нужно подтвердить на телефоне; фоновое воспроизведение на iOS/Android также требует отдельной проверки.

## От чего придётся отказаться

- От обещания единой непрерывной очереди и синхронного текста после выгрузки Mini App. Если это обязательное ядро продукта, основным должен остаться самостоятельный клиент.
- От полного набора дорогих эффектов на слабых телефонах. Сохранены исходные формы осколков; стекло реализовано масками и градиентами, мобильное размытие уменьшено.
- От автоматического точного распознавания слов: буквы интерполируются внутри временных меток слов. Обычный LRC даёт приблизительную подсветку; импорт TTML/Enhanced LRC/JSON и ручная разметка дают заданную пользователем шкалу.
- От обещания полного потока Spotify через каталожный API. Официальный Playback SDK требует Premium и EME; его совместимость с конкретным WebView нужно подтверждать отдельно. [Требования Spotify SDK](https://developer.spotify.com/documentation/web-playback-sdk/reference).

Рекомендуемая архитектура: самостоятельный плеер + Mini App для поиска, коллекции и открытого прослушивания + нативная передача отдельных файлов для фона и профиля. Это сохраняет смысл каждого режима, но не делает три режима одним непрерывным аудиопроцессом.
