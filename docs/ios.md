# Осколок для iPhone

## Почему так устроено

Осколок — это React-приложение, которое уже работает в браузере, в Electron (Windows/macOS) и в Android WebView. Варианты для iOS:

| Вариант | Повторное использование кода | Итог |
|---|---|---|
| React Native / Expo / Flutter | Почти ноль: весь интерфейс (стеклянные осколки, анимации текста, Резонанс) пришлось бы переписать | Отказ: месяцы работы и два разных плеера |
| Capacitor | Высокое, но добавляет npm-зависимости и плагины ради того, что делают 300 строк Swift | Отказ: лишний слой |
| **Swift + WKWebView** (выбрано) | 100 %: та же веб-версия, что `/app`, как в Android-оболочке | Обновления интерфейса без переустановки, нативная аудиосессия |

Оболочка (`ios/`, Swift, UIKit, iOS 15+):

- `PlayerViewController.swift` — WKWebView c `https://oskolok.lol/app`, User-Agent `OskolokIOS/<версия>` (сайт включает режим приложения), свои ссылки внутри, остальные (Telegram, музыкальные сервисы) в системе, офлайн-экран, перезагрузка после выгрузки процесса страницы, нативные alert/confirm.
- `AudioSessionController.swift` — `AVAudioSession` `.playback` + `UIBackgroundModes: audio`: музыка играет в фоне и с выключенным экраном. Прерывания (звонок, Siri) ставят паузу и возобновляют, если iOS разрешает; при отключении наушников пауза.
- `NowPlayingBridge.swift` — экран блокировки, Пункт управления, кнопки наушников. Использует тот же контракт, что Android (`window.OskolokNative.update/clear/setTheme`, команды обратно в `window.__oskolokMedia`). Если WebKit сам поддерживает Media Session API, мост не включается и работают обработчики страницы (`AudioManager`), чтобы команда не пришла дважды.
- `ShellUpdateChecker.swift` — при открытии раз в 6 часов читает `/api/site/releases` и, если есть сборка новее, показывает окно с changelog и кнопкой на гайд обновления.
- Safe Area: страница сама учитывает `env(safe-area-inset-*)` (`viewport-fit=cover`), WKWebView не добавляет отступы.
- Разрешения: только описание камеры (нужно, если в редакторе профиля выбрать «Снять фото»). Микрофон, геолокация, контакты не запрашиваются.

## Сборка

Xcode-проект генерируется из `ios/project.yml` (XcodeGen), поэтому в репозитории нет `.xcodeproj`.

```sh
cd ios && brew install xcodegen && xcodegen generate && open Oskolok.xcodeproj
```

CI: приватный репозиторий `github.com/pexepo/oskolok-ios` (копия каталога `ios/`), workflow `.github/workflows/ios.yml` на `macos-15`:

1. `xcodegen generate`;
2. Release-сборка под устройство без подписи → `Oskolok-<версия>-unsigned.ipa` + SHA256;
3. UI-тест в iOS Simulator: запуск, загрузка oskolok.lol, уход на экран «Домой» и возврат, скриншот;
4. артефакт `oskolok-ios` (IPA, контрольная сумма, скриншоты симулятора) хранится 30 дней.

Обновить копию и пересобрать:

```sh
rsync -a --delete --exclude .git ios/ /tmp/oskolok-ios/ && cd /tmp/oskolok-ios && git add -A && git commit -m "iOS: …" && git push
```

## Подпись и распространение

Неподписанный IPA — это не «готовое к установке приложение»: его подписывает Apple ID того, кто ставит.

| Способ | Что нужно | Ограничения |
|---|---|---|
| Sideloadly (Windows/macOS) | компьютер, кабель, бесплатный Apple ID | подпись 7 дней, до 3 приложений, 10 App ID в неделю на бесплатный аккаунт |
| AltStore Classic | AltServer на компьютере | то же, но продлевает подпись сам по Wi-Fi |
| Ad Hoc | платный Apple Developer ($99/год), UDID каждого iPhone | до 100 устройств в год, профиль на год |
| TestFlight | платный Apple Developer, проверка сборки Apple | до 10 000 тестеров, сборка 90 дней. Приложение с музыкой из открытых источников рискует не пройти проверку (правила App Store 5.2) |
| Альтернативные магазины, Web Distribution | только ЕС, требования Apple к разработчику | аудитория не только из ЕС, поэтому не используем |
| Веб-приложение (PWA) | Safari, без компьютера | фон и экран блокировки на iOS работают нестабильнее, чем в нативной оболочке |

Гайд для пользователей: `/download/ios`. Публикация IPA для бета-тестеров: положить файл в `/var/lib/oskolok/releases` (владелец `oskolok`) и выполнить `releases.js add … --private --beta-only` (см. `docs/site-and-beta.md`).

## Обновления

- Интерфейс и функции обновляются с сайта автоматически (как у EXE/DMG/APK).
- Новая оболочка нужна только при изменении Swift-кода. Тогда: увеличить `MARKETING_VERSION`/`CURRENT_PROJECT_VERSION` в `project.yml`, собрать CI, опубликовать IPA через `releases.js`. Установленные приложения покажут окно обновления, бот и канал — объявление.
- Пользователь переустанавливает IPA тем же способом поверх старого: данные хранятся на сервере.

## Что проверено, что нет

- Проверено на CI: компиляция Release под iOS, сборка IPA, запуск и навигация в iOS Simulator (см. артефакт).
- Не проверено на физическом iPhone: фоновое воспроизведение при заблокированном экране, кнопки на экране блокировки и наушниках, прерывания звонком, установка через Sideloadly/AltStore. Симулятор этого не заменяет.
